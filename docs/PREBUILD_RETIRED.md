# ليه اتعطل الـ prebuild؟

كان فيه سلسلة طويلة من سكريبتات (`scripts/apply-*.cjs`) بتشتغل تلقائيًا قبل كل
`npm run build` — يعني قبل كل نشر على Vercel. كل سكريبت كان بيعمل تعديل نصي
(بحث واستبدال) في ملفات الكود مباشرة وقت البناء، من غير ما التعديل ده يترفع
لـ GitHub أبدًا.

المشكلة اتأكدت بشكل مباشر يوم 2026-08-04:

1. لما السلسلة اشتغلت أكتر من مرة فوق بعضها (في بيئة محلية)، اتصادم سكريبتين
   بيحاولوا يضيفوا نفس الـ state (`exceptionalOpen`) بطريقتين مختلفتين، وده
   كسر البناء تمامًا.
2. الأخطر: بعض السكريبتات كانت بترجّع تعديلات اتعملت واتراجعت عمدًا في نفس
   اليوم — مثال: سكريبت كان بيمسح مسئولي خدمة العملاء من قايمة "التقييم
   الشهري" (بعد ما اتضاف عمدًا في الباك إند)، وسكريبت تاني كان بيرجّع اسم
   الصفحة القديم "تقييم الدكاترة الشهري" ويضيف رابط مكرر ليها في القائمة
   الجانبية.

يعني أي تعديل حقيقي بيترفع على GitHub كان معرض إنه "يتمسح" بصمت في أول نشر
تاني على Vercel، من غير أي تحذير — وده سبب رئيسي محتمل وراء إحساس إن حاجات
بتتصلح وترجع تتعطل "كل شوية".

## الحل

تم تعطيل `prebuild` (بقى مجرد `echo`). الكود الموجود فعليًا في GitHub هو
المصدر الوحيد والنهائي دلوقتي — مفيش تعديلات "شبح" بتحصل وقت البناء.

سكريبتات `scripts/apply-*.cjs` نفسها اتسابت زي ما هي (مش محذوفة) للرجوع
ليها كمرجع تاريخي لو احتجنا نتأكد إيه اللي كانوا بيحاولوا يعملوه، لكن مفيش
حاجة بتشغّلهم تلقائيًا تاني.

لو فيه تحسين حقيقي كان بيتطبق من خلالهم وعايزينه، الطريقة الصح دلوقتي: يتراجع
الملف المطلوب، ويتعمل له تعديل مباشر ومقصود، ويترفع commit طبيعي — مش
سكريبت بيشتغل وقت البناء.
